Strategi migrasi
Nama tabel dan mayoritas nama kolom lama akan dipertahankan agar pemetaan data tetap sederhana. Perubahannya:
MySQL 4.1 → MariaDB modern.
MyISAM → InnoDB.
latin1 → utf8mb4.
Tanggal 0000-00-00 → NULL.
Nilai True/False lama tetap dapat dibaca melalui adapter.
Password lama diterima saat migrasi, kemudian otomatis di-upgrade ke Argon2id ketika pengguna login.
Detail transaksi yang tidak mempunyai primary key akan diberi ID teknis.
Foreign key dan indeks ditambahkan setelah pemeriksaan data.
Tabel baru menggunakan prefiks yang jelas:app_* untuk audit, sesi, konfigurasi, antrean cetak, dan migrasi.
hr_* untuk absensi, jadwal, izin, dan laporan HRD.

Importer akan dibuat repeatable sehingga migrasi dapat dicoba berkali-kali:
Backup database lama.
Impor ke database staging.
Validasi jumlah baris dan checksum/agregat.
Transformasi encoding, tanggal, password, dan engine.
Rekonsiliasi stok, kas, hutang, piutang, dan omzet.
Simulasi aplikasi.
Pada hari cutover: hentikan aplikasi lama, lakukan migrasi final, validasi, lalu aktifkan PWA.
